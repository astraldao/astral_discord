## コマンドの公開範囲（v2.3.1）

一般メンバー向けは /vc とロビーの「行き先を選ぶ」ボタンです。
/vc設定 以下の全操作（一覧・辞書を含む）は「管理者」権限を持つメンバー専用です。
Discordへのコマンド登録時の既定権限と、Botでの実行時チェックを一致させています。
「サーバー管理」権限のみのメンバーは設定コマンドを実行できません。
GitHub用の起動コマンドで再起動するとコマンド登録が更新されます。
Discordの既存のコマンド権限上書きにより一般メンバーに表示される場合は、
サーバー設定 → 連携サービス → このBot → /vc設定 の個別権限を確認してください。
表示が上書きされても、Bot側で管理者以外の設定操作を拒否します。

## 操作の改善（v2.3）

- 行き先は25件ずつ表示し、前へ・次へでページを切り替えられます。「空き状況を更新」で最新の候補を取得します。
- 候補には参加人数・定員（設定がある場合）・カテゴリ名を表示します。
- 順番待ちでは自分の前に何人いるかを表示します。他の予約がキャンセルされると表示も更新します。待ち時間の秒数は音声告知が終わった後からです。
- 順番待ちのキャンセルは即座に予約枠を解放します。音声生成や接続中もキャンセルでき、処理を停止してから次へ進みます。
- /vcを再実行した場合、既存の予約をキャンセルできる案内を表示します。
- 音声準備・告知中・カウントダウンを別々に表示します。失敗時は処理段階に応じた確認先と「行き先を選ぶ」ボタンを表示します。
- ロビー退出・設定変更による取り消しは、それぞれ理由を表示します。
- 相手VCの通知は入室完了・取り消し後もVOICEVOXクレジットを保持します。

19件の単体テストと構文チェックを通過。実際のDiscordでの操作は未検証です。

## QuaxlyでGitHubから導入・更新する

リポジトリ: https://github.com/astraldao/astral_discord

QuaxlyのStartup Commandを次の一行に置き換えて保存・起動します。コンソールへの入力ではありません。

```sh
cd /home/container && curl -fL --retry 2 --connect-timeout 15 --max-time 300 https://raw.githubusercontent.com/astraldao/astral_discord/main/quaxly-bootstrap.sh -o .quaxly-bootstrap.sh && sh .quaxly-bootstrap.sh
```

起動ごとにmainのコードを取得し、npm依存関係とVOICEVOXを確認してBotを起動します。
.env・data・voicevox・.voicevox-venvは上書きしません。すでに導入済みなら設定を引き継ぎます。
初回は辞書・音声モデルの取得に時間がかかります。進行はコンソールに表示します。
GitHub・PyPI・公式音声配布元へのHTTPS接続とPython3.10以上・venv・curl・tarが必要です。
取得やセットアップに失敗した場合はエラーで停止します。GitHubからの起動なのでgitコマンドは不要です。
GitHub版の日本語辞書はセットアップ時にSHA256を検証して取得します。約108MBの辞書データを保存します。

新規導入時は.env.exampleを参考にQuaxlyのファイルマネージャーで.envを作り、Botのトークンなどを設定してください。
トークンとdataはGitHubへ登録しないでください。

# Astral Voice Lobby · v2.2

星モチーフのDiscord VC入室Bot。青紫のEmbed、参加者のアイコン、ボタン、カウントダウンを揃えています。
行き先VC・ロビー・待機秒数・通知音はDiscordコマンドから設定できます。
VOICEVOX:ずんだもんが「○○さんが、まもなく参加するのだ。」と名前付きで告知します。
Bot・設定保存・音声生成を同じサーバーで動かします。外部DB・別の音声サーバー・外部TTS APIは不要です。

## Quaxlyへアップロード

1. File Managerが開くことを確認します。「Wings Connection Unavailable」はホスト側で解決が必要です。
2. ZIPをルートへアップロードして展開します。ルートに index.js / package.json / src が並ぶ状態にしてください。
3. Node.js 24（24.17.0以上）または25を選びます。画像にある nodejs_25 で利用する構成です。
4. ホストの秘密の環境変数に DISCORD_TOKEN と GUILD_ID を設定します。
   環境変数を設定できなければ .env.example を .env としてコピーし、ホスト内で編集してください。
   トークンをチャットや起動コマンドに書かないでください。
5. Startup Commandが編集可能なら次を指定します。

```sh
npm ci --omit=dev --no-audit --no-fund && node index.js
```

代わりに `sh start.sh` でも同じ処理をします。
テンプレートの起動コマンドを維持する場合は、Main File / Bot JS File / JS_FILEなどの欄があれば `index.js` にします。
依存関係のインストールがテンプレートで行われるか、起動ログで確認してください。
実際のQuaxly管理画面の項目名はテンプレートによって異なるため、ない項目を探し続ける必要はありません。
初回インストール済みなら直接 `node index.js` で起動できます。

## ずんだもんを同じサーバーへ導入

音声生成には、同じコンテナ内でPython 3.10以上・venv・curl・tarが必要です。pipとensurepipは不要です。
Linux x64/arm64、glibc 2.34以上が対象です。Node.jsだけのイメージでは動きません。
QuaxlyのイメージにPythonがなければ、Node.jsとPythonを両方使えるイメージへの変更をホストへ相談してください。

シェルを使えないQuaxlyでは、Startup Commandを初回だけ次に変更して保存・再起動します。

```sh
cd /home/container && npm ci --omit=dev --no-audit --no-fund && sh setup-voicevox.sh && npm run voice-test && node index.js
```

「音声生成成功」が出たら、通常のStartup Commandに戻して保存します。
エラー時は通常起動に戻す前に導入ログを確認してください。

シェルを使える環境では初回だけ次を実行します。

```sh
sh setup-voicevox.sh
npm ci --omit=dev --no-audit --no-fund
npm run voice-test
```

セットアップは公式配布URLからVOICEVOX Core 0.17.0・CPUランタイム1.23.2・ずんだもんを含む0.vvm・辞書を直接取得します。
取得対象ごとに進捗を表示し、接続15秒・無転送45秒・1回300秒でタイムアウトします。取得済みの段階は再起動時にスキップします。
モデル等の利用条件を確認してください。初回ダウンロードにはGitHub等への外向きHTTPS接続が必要です。
セットアップ失敗時は、そのログを確認してください。Pythonやvenv不足をBot側だけで解消することはできません。
`No module named pip` が出る旧スクリプトは、更新版setup-voicevox.shで上書きしてください。
更新版は公式の依存なしwheelを専用venvへ展開するため、pipがない既存venvでも使えます。
成功するとテスト音声が `data/voice-test.wav` にできます。File Managerからダウンロードして確認できます。
通常起動時は上記Startup Commandのままで、セットアップを毎回実行する必要はありません。
`voicevox` と `.voicevox-venv` も永続領域に残してください。

音声は初期音量30%、ややゆっくり・抑揚控えめで、始まりと終わりを短くフェードさせます。
耳に優しい音量には個人差があるため、最初にテストしてください。
`/vc設定 音量 パーセント:20` などで10〜60%に調整できます。
合成は必要なときだけ行い、終わるとPythonプロセスを終了します。同じ名前の音声は最大64件キャッシュします。
絵文字・URLなどは読み上げから除き、名前は32文字まで。英字・特殊な名前の読み方はVOICEVOXに依存します。
音声生成に失敗した場合は移動を中止します。無音のまま自動で入室しません。
音声告知の投稿には必要なクレジット `VOICEVOX:ずんだもん` を表示します。

**旧版から更新する場合**: 先に停止し、dataフォルダと.envを保持してソースを上書きします。
旧版のLOBBY_VC_ID / TARGET_CATEGORY_ID / ENFORCE_LOBBY / VOICE_CHIME環境変数はv2では使いません。
Discordで設定し直してください。今後の更新時もdata/settings.jsonを消さないでください。

## DiscordのBotを準備

https://discord.com/developers/applications でアプリとBotを作り、トークンを発行します。
招待設定は `bot` と `applications.commands`。
Botには「チャンネルを見る」「メッセージを送信」「埋め込みリンク」「メッセージ履歴を読む」「接続」「発言」「メンバーを移動」を許可してください。
管理者権限と特権Intentは不要です。チャンネル・カテゴリの権限上書きにも注意してください。
GUILD_IDはDiscordのサーバーIDです。開発者モードを有効にするとコピーできます。

## Discordで初期設定

起動ログに「準備完了」が出たら、サーバー管理権限を持つ人が以下を実行します。

1. `/vc設定 ロビー チャンネル:入室ロビー`
2. `/vc設定 行き先追加 チャンネル:好きなVC` を候補ごとに実行
3. `/vc設定 パネル設置`

チャンネルはDiscordの選択欄から指定できます。IDのコピーは不要です。
設定はその場で反映され、data/settings.jsonに保存されます。外部DBは不要です。
設定変更時は、移動開始前の入室待ちを取り消します。

| コマンド | 用途 |
|---|---|
| /vc | 自分専用の行き先選択を開く |
| /vc設定 ロビー | ロビーVCを指定 |
| /vc設定 行き先追加 | 候補にVCを追加 |
| /vc設定 行き先削除 | 候補からVCを削除 |
| /vc設定 一覧 | 現在の設定を確認 |
| /vc設定 待機秒数 | 3〜15秒に変更。初期値5秒 |
| /vc設定 通知音 | ずんだもんの名前付き音声ON/OFF |
| /vc設定 音量 | 10〜60%。初期値30% |
| /vc設定 直接入室 | 許可:trueなら直接入室可、falseなら検出後ロビーへ戻す |
| /vc設定 パネル設置 | ロビーのパネルを設置・更新 |

初期設定は通知音ON・直接入室を検出後ロビーへ戻す設定です。
入室先は通常のVCだけで、本人の閲覧権限・空き状況・Bot権限で絞り込んで表示します。
管理者が行き先に登録したVCは、本人の「接続」権限がなくてもBotによる移動を許可します。「チャンネルを見る」権限は必要です。
候補は125件まで。設定一覧は先頭25件と残り件数を表示します。

## 入室の流れ

ロビーVCに接続 → ロビーのチャットで「行き先を選ぶ」 → VCを選択 → 入室待ち → 参加予告 → カウントダウン → 移動。
相手のVCチャットには入室者の名前とアイコンが表示されます。名前付き音声を一度流し、読み上げ完了後からカウントダウンします。毎秒のチャイムは鳴りません。
自分専用のカウントダウンには進行状況とキャンセルボタンが表示されます。
ロビー退出・キャンセル・権限変更・通知失敗では移動しません。
複数VCの通知は順番に処理します。順番待ちは設定秒数に含まれず、音声完了後（音声OFFならテキスト予告後）から待機します。
再起動すると予約は消えるため、再度選んでください。

## 運用上の条件

- 設定ファイルを残すため、Quaxlyの永続的なファイル領域にdataフォルダを保持してください。
- 外向きのDiscord Gateway接続と、音声用UDP通信が必要です。音声が接続できない場合は `/vc設定 通知音 有効:false` でテキストのみを試してください。
- 直接入室の制御は接続を検出して戻す方式です。最初の接続を完全に防ぐものではなく、Bot停止中は制御できません。
- 行き先の「接続」権限をメンバーには拒否し、Botには許可できます。ロビーには本人が接続できる権限を付けてください。
- 登録した行き先は、閲覧できるロビー利用者全員がBot経由で参加できる設定になります。個別の「接続」拒否はBot経由の入室制限には使えません。
- 満員判定とDiscordでの移動は同時に確定できないため、他の人が同時に入室すると移動失敗になる可能性があります。
- ロビーを変更したら `/vc設定 パネル設置` で新しいロビーに設置します。古いロビーのパネルは管理者が削除してください。
- Botが他人の音声を録音する処理はありません。外部のTTS APIも使いません。
- 512MB枠への適合はQuaxly上では未確認です。音声生成時にはBotとPythonが同時にメモリを使います。まずテストを行い、管理画面でメモリ・ディスク使用量を確認してください。

## 検証

npm test: 設定保存と再読み込み、同時設定更新、壊れた設定の検出、候補制限、権限、満員判定、キュー直列実行、Discord表示・コマンドデータの検証。
npm run check: 全ソースの構文チェック。
名前の整形・WAV検証・音量制御・フェード・キャンセルの単体テストも含みます。
ローカルLinux x64環境で公式Coreによる名前付きずんだもん音声の生成を確認しています。

これはQuaxlyの計測値でも、Discord Botを含む合計メモリでもありません。

実際のDiscordとQuaxlyへの接続・音声・移動は未検証です。
導入後は2人で通知・移動、途中キャンセル、ロビー退出、同時入室、権限のないVC、再起動後の設定維持を確認してください。

## 英語・日本語の読み方改善（v2.2）

英語はalkana由来の49,216語をカタカナ読みへ変換します。英語そのものの発音ではなく、日本語の告知に馴染ませるための変換です。
一般英単語は大文字小文字を区別せず、未登録のCamelCaseは分割して照合します。未知語は元の表記をVOICEVOXに渡します。
日本語はpyopenjtalk-plus 0.4.1.post9の改良システム辞書を使用します。ライブラリ自体や追加の学習モデルは導入しません。
Coreへの辞書読み込みと音声生成をローカルで確認済みですが、すべての名前の読み・アクセントが正しくなる保証はありません。

更新時はsrc・scripts・dictionariesをまとめて上書きし、dataと.envを保持して再起動してください。
Startup Commandは通常用のままで大丈夫です。新しい日本語辞書は最初の音声生成時に自動展開します。
辞書アーカイブは約24MB、展開後は約108MBの追加ディスク領域を使います。初回生成は展開の分だけ遅くなります。
従来の音声キャッシュは再利用しません。最大64件に収まるよう順次整理します。

管理者が誤読を直すには次を使います。登録は100件までで、data/settings.jsonに保存されます。

```text
/vc設定 辞書登録 単語:Astral 読み:あすとらる
/vc設定 辞書登録 単語:小鳥遊 読み:たかなし
/vc設定 辞書一覧
/vc設定 辞書削除 単語:小鳥遊
```

表示名全体の登録が最優先です。英語は単語単位でも上書きできます。日本語名は表示名全体を登録してください。
飾り文字は取り除き、名前の先頭32文字を照合します。たとえば「小鳥遊 太郎」はその全体を登録します。
辞書の変更は待機中の予約を取り消します。再選択してください。

辞書の出典・ライセンスはdictionaries/NOTICE.mdを参照してください。
