# スペックと音声の処理速度を診断する

管理者が `/admin → 運用・管理 → 動作診断` を開くと、稼働版・音声環境・権限に加え、CPU上限・CPU並列度・メモリ使用量/上限を確認できます。診断画面を開くだけでは合成テストを開始しません。

## 処理速度を測る

1. 読み上げとVC入室を終了する。
2. 動作診断の **「処理速度を測る」** を押す。
3. 説明を確認して **「測定を開始」** を押す。
4. 準備・合成・Opus変換の順に測定する。約5秒ごとの自動更新と「状態を更新」で現在の段階を確認できる。中止は「測定を中断 → 中断を確定」で行う。
5. 完了すると同じ非公開画面に結果を表示する。別画面へ移動した場合は上書きせず、測定画面を開き直すと結果を確認できる。

固定文「こんにちは。音声の処理速度を確認しています。」を使い、チャンネルの投稿は取得しません。VCへの接続・音声送信・音声ファイルの保存は行いません。バックアップ読み上げの起動フラグがOFFでも、音声環境があれば測定できます。

| 測定項目 | 意味 |
|---|---|
| モデル準備 | 新しいPythonプロセスを起動し、ずんだもんのモデルと分割合成を準備するまで |
| 先頭音声まで | 準備完了後に固定文を渡してから、最初のWAVを受信するまで |
| 合成完了 | 固定文の合成要求から、全分割データと完了通知を受信するまで |
| 音声の長さ・片数 | 生成したPCMの総時間と分割データ数 |
| 最長の分割待ち | 2片目以降で、前の音声データから次の音声データが届くまでの最大時間 |
| Opus変換 | 最初の分割音声・最大1秒分を変換する時間。v3.37以降は専用ワーカーの初期化と変換の内訳も表示 |
| 実時間比 | 合成完了時間 ÷ 生成した音声の長さ。1未満なら再生時間より速く合成 |
| CPU制限発生 | 測定前後のcgroupの制限発生期間数 ÷ 実行期間数。CPU速度の割合ではない |

測定は1回ずつ実行し、終了・失敗・中断の後は30秒間隔を設けます。モデル準備90秒、先頭音声30秒、分割音声の進捗待ち15秒、合成全体60秒、Opus初期化30秒＋準備後の変換5秒（合計35秒）を上限とします。音声処理との同時実行を防ぎ、測定中の更新・再起動は見送ります。

モデル準備は新しいPythonプロセスで行いますが、OSのファイルキャッシュは削除しません。結果はその時点の負荷を含む1回の実測です。Discordの権限確認、通信、VCで聞こえるまでの時間は含まず、300ms以内の読み上げを保証する測定ではありません。

## スペックの見方

CPU上限は確認できるcgroupの割当をコア換算で表示します。たとえば0.25コアは、CPU時間の上限が1コアの約25%である設定です。CPU並列度はプロセスから利用可能に見える論理CPU数で、専用コアの数ではありません。上限を読み取れない場合は「未確認」と表示し、確認できるcgroupに上限がない場合は「未設定」と表示します。ホスティングの上位の制限やCPUの共有状況まで判定できるとは限りません。

メモリはコンテナで確認できる使用量と上限です。上限が不明でOSの値を使う場合は参考値と表示します。測定結果の使用量は終了時点の値で、測定中のピークではありません。CPU制限のカウンターもコンテナ全体の値なので、他の処理の影響を含みます。

## 止まった箇所を確認する

失敗時にも、受信できた片数・先頭音声までの時間など、そこまでの結果を表示します。停止理由には「モデル準備」「文章解析」「分割合成」「音声受信」と対象の片数、経過時間、最終音声からの時間、実際のスレッド数を表示します。

通常の読み上げでの直前の停止理由も動作診断に表示します。コンソールには稼働版と、同じ固定項目の数値を記録します。投稿本文・生成音声・トークン・生の例外・ファイルパスは記録しません。

| 結果 | 次に確認すること |
|---|---|
| モデル準備で失敗 | Python・音声ランタイム・モデル・辞書と、準備中のCPU/メモリ |
| 固定文でも分割合成が止まる | 対象の片数・CPU上限・制限発生状況・使用スレッド数 |
| 実時間比が1以上 | CPUの割当と負荷。スレッド数1の測定と比較する方法もある |
| 合成は成功しOpusで失敗 | 音声エンコーダの導入状態とNode側の処理負荷 |
| 固定文は成功し投稿時だけ停止 | 読み上げの直前の停止理由と、固定文の測定結果を比較する |

スレッド数を試す場合は `/admin → 運用・管理 → ENV・起動設定` から変更・保存し、「Botを再起動」で反映します。診断自体は設定を自動で変更しません。

現在の測定画面には直前の結果を表示し、別の「測定履歴」に終了済みの直近5件を保持します。成功・失敗・中断を含み、メモリ内だけのためBot再起動で消えます。画面の本人・元チャンネル・10分期限・世代・現在の管理者/閲覧権限を検証し、測定の中断は開始した画面から行います。

## 測定履歴を比較・取り出す

1. 処理速度の画面で **「測定履歴」** を押す。
2. 選択欄で、確認したい測定を選ぶ。
3. 完了した測定なら、保持されている直前の完了測定との差を確認する。途中の失敗・中断は比較元にしません。
4. **「選択したJSONを取得」** で、選択した履歴と比較元のレポートを本人だけの画面に添付する。
5. **「現在の測定へ」** で測定の進行状況・再測定へ戻る。

差は「選択した測定 − 比較元」です。負の値はその測定値が小さいことを示します。Bot版・合成方式・スレッド数・CPU割当・メモリ上限などの条件が異なる場合や確認できない場合は、条件差・未確認項目を表示します。単発の差だけで最適化の効果やホスト混雑を断定しません。

JSONは固定文による測定の数値・固定の分類名・日時・Bot版だけです。投稿本文・音声・トークン・ENV・ファイルパス・利用者/チャンネルIDは含めません。レポート自体は公開投稿せず、端末へ保存できます。5件を超えて古い履歴が外れた場合は、最新の選択欄から選び直してください。自動測定・永続保存は行いません。

## 画面が更新されない・中断と表示された場合

v3.36.1以降は、Discordへの進捗返信や権限取得が一時的に失敗しても、開始済みの固定文の測定を中断しません。「動作診断 → 処理速度を測る」から開き直すと、測定中の状態または直近の結果を再表示できます。結果を表示するときには現在の管理者権限と閲覧権限を確認します。測定にはこれまでと同じ時間上限があり、無期限には続きません。

「確認操作で測定を中断しました」は開始した画面で中断を確定した場合、「Bot停止により測定を中断しました」はBotの停止処理による中断です。タイムアウトは失敗理由コードを表示します。Botの再起動後は結果が消えるため、過去の画面には更新前の表示が残る場合があります。

v3.36.0では、開始後の画面更新が失敗すると測定自体も中断してしまう不具合がありました。操作せずに「中断」となった場合は、まず管理者のバージョン管理からv3.36.1以降へ更新して測定し直してください。

## v3.37以降のスレッドと音声変換

ENV画面の合成スレッド数は「上限」です。保存値を読み、利用可能なCPU並列度とcgroupで確認できるCPU割当の整数部分までに制限します。最小は1です。設定上限3・CPU1コアなら実行1と表示します。保存済み設定や `.env` を変更する処理ではありません。CPU上限を確認できない場合は利用可能な並列度を使います。ホストの上位制限や他利用者との競合まで検出できるとは限りません。

Opusの総時間には、診断のために新しく起動する変換ワーカーの初期化を含みます。「初期化」と「変換」の内訳を区別してください。通常のバックアップ読み上げは接続準備時に初期化し、同じVC接続中は変換環境を再利用します。接続の準備時間を、各投稿の読み上げ開始時間に足し込む必要はありません。

## v3.37.1以降の操作期限と中断元

開始と「状態を更新」は同じ行に固定し、中断は別の行にあります。「測定を中断」を押しても測定は続きます。30秒以内に「中断を確定」で中止するか、「測定を続ける」で戻れます。確認が期限切れの場合や古い画面からは確定できません。

準備・合成中は約5秒ごとに進捗を表示するので、長い準備中にボタンを繰り返し押す必要はありません。表示権限を確認できない・画面を編集できない場合は自動更新を止めますが、固定文の測定は既存の時間上限内で続け、結果を保存します。

コンソールの「速度測定の操作」は、受付失敗（ack）、確認表示（cancel-prompt）、中断確定（cancel-confirmed）、実際の中断（cancelとcause）を区別します。causeは確認済みuser・Bot停止shutdown・未分類systemです。ageMsはBotが受付処理を始めた時点で操作発行から経過した時間、ackMsは受付処理にかかった時間で、システム時計に基づく値です。トークン・投稿本文・アカウント/チャンネルIDは記録しません。

10062はDiscordの操作受付期限切れです。すでに期限切れになった操作を同じトークンで再送しても復旧しないため、再送を避けます。測定の合成失敗を意味するコードではありません。画面を開き直すと、現在の管理者・閲覧権限を確認して結果を参照できます。

## v3.38以降の合成方式

結果に「特徴量を共有して連続生成」または「短い句をまとめて生成」を表示します。前者は文章全体の情報を一度だけ計算する方式、後者は対応環境の確認に通らなかった場合の公開APIです。どちらも同じ声・文字数・投稿順で動作し、方式の選択にENVの変更は必要ありません。

前者で停止した場合は、処理中の片数に加え、受信したフレーム数と全体のフレーム数を表示します。これは音声生成の進捗で、Discordへの送信や聴取完了の割合ではありません。CPU負荷に応じて分割が変わるため、片数だけで旧版と速度を比較せず、「先頭音声まで」「合成完了」「実時間比」を確認してください。

## v3.38.1以降のCPU実行時間

経過時間とは別に「CPU実行」と「Opus CPU」を表示します。前者は準備・先頭音声・合成に使ったPythonプロセスのユーザー＋システムCPU時間で、ネイティブ合成の全スレッドを含みます。後者はOpus専用ワーカーの現在のスレッドに限ったCPU時間です。初期化はワーカースレッド開始後の累計、変換はメッセージの開始・分割変換・終了処理の合計です。Nodeの本体やV8の補助スレッドのCPU時間を足す値ではありません。

CPU実行時間に待機・sleepは入りません。経過時間との差にはOSの実行待ち、入出力、IPC、計測範囲の違いなどを含みます。差が大きくても、それだけで共有ホストの混雑やCPU制限を断定しないでください。CPU実行時間自体が長い場合も、CPU性能・処理量・コンパイル等の影響を区別できるとは限りません。合成は全スレッドの合計なので、複数スレッドでは経過時間を超えることがあります。

先頭音声と合成のCPU時間は投稿ごとにリセットし、準備とは分けます。測定値を返さない旧形式や欠けた値を0msと扱いません。一部の値だけがある場合、残りは「未計測」と表示します。不完全な合計は表示しません。追加の固定文や負荷試験を自動実行せず、既存の測定処理のCPUカウンターを読むだけです。[実モデルと1秒の意図的待機による検証](performance/voice-cpu-diagnostics-2026-10-17.json) は実機の共有負荷を再現したものではありません。

## v3.38.2以降の準備タイムアウト

準備中は、Python起動待ち・音声ライブラリ・辞書・音声ランタイム・日本語解析・合成器・モデルを開く処理・モデル読込・準備用文章解析・分割音声の準備を区別します。各処理の直前に固定名とCPUカウンターを送り、準備が終わる前でも最後に到達した箇所を確認できます。動作中は既存の自動更新/「状態を更新」に表示し、停止時も結果へ残します。「この段階」はBotが通知を受信してからの時間で、通知自体の配信待ちは含みません。

**準備CPU（最終記録）は、最後のチェックポイント時点の値です。停止した瞬間のCPU時間ではありません。** 長いネイティブ処理中には更新されないため、この値が小さいだけでCPUを使っていないとは判断できません。辞書展開の子プロセスのCPUもPython本体の値には含みません。Pythonからの通知が1件もないときは「Pythonの起動待ち」、CPUは欠測です。

準備が未完了で停止した場合も「モデル準備経過」を表示し、成功した準備時間と区別します。タイムアウトの監視が予定より1秒以上遅れた場合は「監視タイマーの遅れ」を表示します。本体の処理待ち・OSでの実行待ち・一時停止等を含み、その原因を特定する値ではありません。90秒の準備上限、先頭30秒・分割待ち15秒・合成全体60秒は同じです。チェックポイントだけで期限は延長しません。

10062はDiscordの操作受付期限切れです。ageMsはBotが受付処理を始める時点で操作作成から経過していた時間、ackMsはその受付応答にかかった時間です。配信・本体の処理待ち・通信・Discord側の待機などを含み、音声モデルのCPU時間とは別の値です。実行・権限・期限の確認や失敗時の再送抑止は従来どおりです。

## v3.39以降の分割数の比較

合成方式とプロトコルは「特徴量を共有して連続生成」「3」のままですが、文章と処理速度に合わせて2つ目の分割を調整します。固定文が4片から3片になる場合があります。最初の音声は同じ長さで、先頭待ちを短く見せるために無音の小片を増やすことはありません。

CPU実行時間と全文の合成完了時間を比較してください。Opusの診断に使う先頭の長さも以前と同じです。ホストの負荷で分割が変わるため、片数だけで性能を判断せず、同じ文・スレッド数・環境で複数回確認してください。後半の長い分割が届くまでの「最長の分割待ち」と、実際の再生時の途切れの長さは別の値です。

## 既知の脆弱性を確認する

「脆弱性診断」は動作診断からも開けます。音声ファイルやVC権限の確認とは別に、実行中の版のnpm依存情報をOSVへ照会します。画面を開くだけでは照会しません。[診断の対象と手順](SECURITY_SCAN.md)。

## v5.1 対処へ進む

動作診断の「対処の手順」で、未登録のVC・権限不足・未確認の音声構成・直前の読み上げ停止に応じた案内を表示します。VC設定・音声設定・ENV・処理速度の測定へ進めます。案内は診断時点の結果に基づき、設定変更や再起動は実行しません。「診断を更新」で状態を確認し直してください。

## ダイスが反応しない場合（v5.3）

チャットダイスのON/OFFと、通常投稿かメンション付き投稿への対応かを動作診断に表示します。状態はBotのIntent設定に基づき、実際の返信を試験するものではありません。通常投稿への対応にはMessage Content IntentをPortalで有効化し、Botを再起動してから再診断してください。
