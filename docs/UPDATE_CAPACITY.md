# 更新前の容量確認

v4.3.0以降は、`/admin → バージョン管理 → 更新を確認` で、現在の版から確認した新版へ更新する容量の目安を表示します。「更新内容を確認」に進んでも同じ対象の数値を確認できます。v6.13以降は概要に要約を表示し、選択欄の「容量の内訳」で以下の全項目を確認できます。

| 表示 | 計測するもの |
|---|---|
| コード圧縮ファイル | 対象コミットの配布元がサイズを返す場合の取得量。返さない場合は未確認・取得上限20 MiB |
| 依存パッケージ | 現在の導入状態と新版のlockを比較。再利用予定、または新規取得が必要かを表示。新規取得のサイズは未確認 |
| 新版コード | 対象コミットの全ファイルの合計。展開後サイズの目安 |
| 保存データの控え1組 | `data` 内のファイルサイズの合計。内容は読まず、件数・深さ・容量・時間を制限して調べる |
| 小計 | 新版コードとデータ控え1組の合計。依存を再導入する場合の容量は別 |
| 最低空き・確認時の空き | 更新処理の最低条件200 MiBと、OSが報告する空き容量 |

更新は差分配信ではなくコード一式を取得します。旧版も保持し、更新中は圧縮ファイル・展開用の一時領域・復旧時の追加の控えも使います。小計はファイル合計の目安で、ディスクの割当単位・npmキャッシュ・依存再導入を含む最大使用量ではありません。古い版や控えの整理で減る分も差し引きません。

OSが示す空き容量と、ホスティング側の契約・コンテナの割当上限が一致しない場合があります。200 MiB以上と表示されても、新規依存やデータ量によって追加の空きが必要です。空き容量の最終確認は更新処理でも行います。

計測は管理者が「更新を確認／更新を再確認」を押したときだけ実行します。同じ現在版・新版の結果は30秒間再利用します。外部取得は固定GitHubリポジトリのサイズ情報・ファイル一覧・依存lockだけで、更新用アーカイブ本体は取得せず、npm・更新・削除を実行しません。データ内容・ENV・トークンを計測結果へ含めず、結果をファイル保存しません。

権限失効・画面の終了時は結果を表示しません。通信制限や容量制限で取得できない項目は「未確認」とし、計測だけの失敗で更新を止めません。確認した現在版・対象コミットが変わった場合は古い数値を表示しません。

この機能自体はv4.3.0へ手動更新した後から利用できます。親プロセスの入れ替え・ホスティング再起動・新しいENVや依存パッケージは不要です。従来の手動更新・確認済みコミットへの固定・dnd表示を維持します。


## v6.13 要約と容量不足の案内

概要は取得量・依存の再利用/新規取得・追加保存の小計・OSの空きを短く表示します。詳細と制限は「容量の内訳」、手順は「更新の流れ・注意点」で確認できます。表示切り替えでは通信・再計測・更新を実行せず、確定前の対象コミットも維持します。

有効な同じ対象の見積もりでOSの空きが200 MiB未満なら、先頭に注意を表示します。未確認や古い対象の値からは判定しません。確認時点の目安であり、200 MiB以上でも新規依存やホスト側の契約上限によって不足し得ます。表示だけで更新を始めたり、ホストの割当を変更したりはしません。
