# Botを再起動する

管理者が **`/admin → Botを再起動 → 再起動を確認 → 再起動する`** を押すと、現在のバージョンでBotを起動し直します。「運用・管理」や「ENV・起動設定」の画面からも開けます。

1. 読み上げを停止し、VC入室・ゲーム・処理中の操作が終わったことを確認する。
2. 再起動画面で、稼働中と次回起動時の設定を確認する。
3. 「再起動を確認」から「再起動する」を押す。
4. 接続が一時中断する。再接続後、`/admin → Botを再起動` を開き直し、完了状態を確認する。

再起動中は **dnd（取り込み中）・再起動中** を表示し、完了後は通常の表示へ戻します。GitHubからの最新版取得・バージョン変更・依存関係の導入は行いません。コードを更新するときは「バージョン管理」を使ってください。

## 起動設定を反映する

`/admin → 運用・管理 → ENV・起動設定` で値を確認・保存し、同じ画面の「Botを再起動」を使います。保存だけでは、稼働中のIntentや合成スレッド数は変わりません。バックアップ読み上げをONにする場合は、先にDiscord Developer PortalでMessage Content Intentを有効にしてください。

起動が90秒以内に完了しない場合は、直前に稼働していた2項目の起動設定へ戻し、同じバージョンで復旧を試みます。再接続後の画面には「起動設定を戻して復旧しました」と表示します。保存値も復元するため、原因を解消してから設定し直してください。`.env` やトークンは変更しません。

Discordやホスティング自体の障害など、元の設定でも起動できない場合はQuaxlyのコンソールから状態を確認してください。再起動ボタンはBotが応答できるときに利用できます。ホスティング全体やVOICEVOXの再導入は行いません。

## 処理中で再起動できない場合

読み上げ・VC入室・ゲーム・別の操作が進行中の場合や、更新・再起動がすでに実行中の場合は受け付けません。終了後にもう一度確認してください。後から自動実行する予約は残しません。確認後に起動設定が変わった場合も、画面を開き直して確認が必要です。

再起動後は、古い非公開画面のボタンや入力途中の下書きは使えません。`/menu`・`/admin` から開き直してください。保存済みの予定・設定・チップ残高は保持します。

## v3.34以前からの初回切り替え

**この版への手動更新後だけ、Quaxly側で一度Botを再起動してください。** Bot本体の更新では、常駐している起動プロセスは切り替わらないためです。未対応の起動プロセスでは、画面にこの手順へのリンクを表示し、再起動の実行ボタンを表示しません。

README記載のStartup Commandを使っていれば、そのままQuaxlyの再起動を実行できます。最新の起動スクリプトが保存済みのローカル版と、その版の起動プロセスを選びます。最新版のBotを自動適用する動作はありません。古い固定の起動コマンドを使っている場合は、[READMEのStartup Command](../README.md#quaxlyでgithubから導入更新) に合わせてください。

切り替え後は `/admin → Botを再起動` の確認ボタンが使えます。以後のENV・起動設定の反映はDiscordから完結します。
