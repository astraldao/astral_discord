# チャットダイス・サイゼロール（v6.10）

チャンネルにダイスの依頼を投稿すると、元メッセージへのリプライで結果を返します。ゲーム共通の紫色のカードに結果・式・内訳をまとめます。複数個なら合計とすべての出目、補正があれば符号付きの補正を表示します。複数の式も1枚にまとめます。抽選にチップは使いません。曖昧な短文のJev補助判定は、設定した有料モデルを使う場合にAPI料金が発生します。

| 投稿例 | 動作 |
|---|---|
| `1D100` | 100面ダイスを1個 |
| `1D4,3D10` | 4面1個、10面3個を別々に集計 |
| `判定1D100` / `ダメージ 3D10` | 判定やダメージの短い宣言として実行 |
| `3D10を振って` / `1D100振ってくれる？` / `roll 3d10` | 明示的な依頼として実行 |
| `2D6+3` | 2個の合計に3を加算 |
| `1D100って何？` / `1D100を振らない` | 反応しない |
| コード、引用、URL、ネタバレ内の表記 | 対象外 |

大文字・小文字・全角数字に対応します。文脈は保守的なルールで判断し、説明・説明を求める質問・過去の話・否定・引用符を含む文章や、曖昧な長文には反応しません。現在の1投稿だけを対象に、明確な依頼は有限の言葉・文章の形で判定します。関連する曖昧な短文は、設定済みのJevへ補助判定を依頼します。会話履歴は読みません。すべての自然文を必ず正しく理解する保証はありません。反応しない場合は、ダイス表記だけの新しい投稿で依頼してください。編集しても再実行しません。

## 高度なダイス式（v6.10）

式だけを投稿するか、「4d6kh3ふって」のように短い依頼へ添えて使います。通常文30文字未満、保護領域・文脈・権限の確認は従来どおりです。明確な式はJevなしで処理し、曖昧な短文をJevが承認した場合も、式の内容や出目はBot内で決めます。

| 記法・投稿例 | 動作 |
|---|---|
| `(2d6+3)*2` | 括弧と `+ - * /` の優先順位に従って計算。`×`・`÷`・全角にも対応 |
| `4d6kh3` / `4d6kl3` | 高い3個／低い3個を採用し、残りを除外 |
| `2d20kh1` / `2d20kl1` | 2個から高い方／低い方を採用 |
| `有利で1d20` / `1d20を不利で` | 1個のダイスを2個にして高い方／低い方を採用。`1d20+5` の補正も維持 |
| `4d6r1` | 1が出たら、その値を一度だけ振り直す。再び1でも繰り返さない |
| `4d6r<=2` | 2以下を一度だけ振り直す。`< <= > >= = == !=` に対応 |
| `1d6!` | 最大値が出るたび追加で振り、元のダイスへ加算 |
| `5d10cs>=8` | 各ダイスの8以上を成功として数える。条件の比較記号は上と同じ |
| `1d100<=70` | 最終合計と目標値を比較して成功／失敗を表示 |
| `(2d6+3)*2>=20` | 計算後の結果で比較。比較は式の末尾、目標値は±100万以内の整数 |
| `4d6kh3,1d100<=70` | カンマで別の式として実行し、1枚のカードへ集約 |

`1d6+1d6` は加算、`1d6,1d6` は独立した2式です。従来の `1d6/1d6` のような区切りは、v6.10から割り算として扱います。独立させたい場合はカンマを使ってください。ダイスは `NdM` を明記し、数値だけの計算や、暗黙の掛け算・べき乗・剰余・関数呼び出しには対応しません。

### 組み合わせの順序

**振り直し → 爆発 → 採用 → 成功数 → 四則演算 → 目標値比較** の順です。`r`・`!`・`kh/kl`・`cs` は各1回まで指定でき、記述順は結果の処理順を変えません。

例えば `3d6r1!kh2` は、1を一度だけ振り直し、最終値が6なら追加分も同様に処理します。追加分は元のダイスへ合算し、その合計が大きい2個を採用します。同値なら元の出目の順で採用します。`cs` を併用した場合も、追加分を含む元のダイス1個の合計を1回の成功判定へ使います。追加分を別の成功機会として数える方式ではありません。

有利／不利の日本語指定は、1つの式・1組のダイス・元の個数1個に限ります。すでに `kh/kl` が付いた式や複数のダイス組には重ねず、目的の個数と `kh/kl` を直接指定してください。TRPGシステム固有のクリティカルや難易度区分は追加していません。

### 内訳と上限

結果を見出しに、採用した値・除外した値・振り直し前→後・爆発の追加分を本文へ表示します。カードでは除外した値に取消線を付けます。文字返信でも全出目を残し、通常は除外した値を括弧で示します。文字数が多い場合は、式と全出目を優先した簡潔な表示へ切り替えます。内訳の番号は式に登場するダイスの順です。

高度な式は1投稿で最大5式・ダイス5組、各組1〜100個・2〜100万面、**振り直しと追加も含めて総抽選200回**です。元のダイスはすべて振れるよう枠を確保し、追加は1個につき10回まで。上限に達して必要な抽選を続けられなかった場合は参考値と明記し、成功／失敗を確定しません。上限に達しても勝手な再実行はしません。

式は数値を正規化した後で120文字まで、括弧・単項符号の入れ子は16段、数値定数は0〜100万の整数です（小数は割り算で指定できます）。計算結果は±1兆の範囲で扱い、0で割る計算や範囲外は「計算できません」と、取得済みの全出目を表示します。小数の表示を丸める場合は「約」と示し、最大10桁の有効数字にします。比較そのものは表示用の丸め前に行います。新しいコマンド・ボタン・依存・保存データは追加しません。

[高度な式の表示見本（架空のHTML）](previews/rolls-v6_10.html)は実際の送信データを使っています。再生成：`node scripts/preview-rolls.js --advanced > docs/previews/rolls-v6_10.html`。Discord実機画面ではありません。

## 依頼と文章の判定（v6.5）

| 投稿例 | 判定 |
|---|---|
| `1d10ふって` / `1d10をふってください` / `１ｄ１０ ﾌｯﾃ` | 同じ1D10の依頼として実行 |
| `1d10ふってほしいです` / `1d10ふってー` / `1d10おねがい` | 短い依頼として実行 |
| `1d10まわして` / `1d10ころがして` / `1d10ろーるして` | 同じ依頼として実行 |
| `1d10をふってもらえますか？` / `1d10をふってくれない？` | Botへ振ることを依頼する形として実行 |
| `1d10ふってもいい？` / `1d10ふれる？` | 自分の許可・可能性を尋ねる形なので見送る |
| `1d10ふってくれない` | 疑問符なしでは不満・叙述との区別がつかないため見送る |
| `1d10ふらない` / `1d10ふるな` / `1d10ふった` | 否定・禁止・過去の話として見送る |
| `お風呂の温度は1D100度！！` / `お風呂の温度は2D10+30度` | 温度を決める宣言として実行 |
| `今日の運勢は1D100点` / `私のHPは3D10` | 点数や能力値を決める宣言として実行 |
| `お風呂の温度は1D100度だった` / `例：お風呂の温度は1D100度` | 過去の話・説明として見送る |
| 引用・コード・ネタバレ・URL・リンクの表示名の中 | 実行しない |

数値を決める文章は、**温度・点数/運勢・HP等/ダメージ・時間・回数等・予算等・年齢/寿命・長さ等・重さ**の項目と、は/が/を/代入記号、1つのダイス式、対応する単位という形を判定します。単位は省略できます。文末の記号は許可しますが、説明や過去の話などの追加文は見送ります。温度に円など、項目と単位が合わない形も見送ります。あらゆる自由な文章を意味理解する機能ではありません。

結果は既存のカードで式・合計・全内訳を返します。温度や予算などの周囲の文は結果へコピーせず、実際の設定温度・残高・予定なども変更しません。単独の `1D10` は1〜10のまま、サイゼ限定の10→0変換も維持します。

「くれない？」「もらえない？」は、振る動詞に直接つながった疑問形だけを依頼として扱います。「くれませんか」のように依頼の形が明確なものも受け付けます。単に否定語を無視する判定ではありません。Discordの複数行引用（`>>>` 以降）や、URL付きリンクの表示名も実行対象から外します。

明確な依頼はAPIキーなしで動きます。関連する曖昧な短文は、Jevが設定されていれば補助判定へ送ります。未設定・判定失敗・閾値未満では返信を見送ります。[設定と判定の順序](DICE_JEV.md)。

## サイゼロール

`サイゼロール`、`サイゼロールして`、`サイゼロールお願い`、`サイゼロールしてくれる？`、`サイゼロールふって`、`サイゼロールおねがい` と投稿すると、元の投稿へのリプライで番号を返します。半角カナの `ｻｲｾﾞﾛｰﾙ` にも対応します。説明の `サイゼロールとは？`、過去の話、否定、引用やコード内の呼びかけでは実行しません。判定は保守的なルールです。

式は **`(1D3)(1D4)0(1D10)`**。独立した3回の抽選結果と固定の `0` を、足し算せず順番につなぎます。

```text
🎲 サイゼロール → 2407
(1D3)(1D4)0(1D10) → (2)(4)0(7)
※ 実在するメニュー番号とは限りません。
```

**サイゼロールだけ**末尾の1D10で10が出たら0に変換し、必ず4桁にします（例：`(3)(4)0(10)` → `3400`）。抽選は1〜10を等確率で振り、返信には変換前の出目も表示します。通常の `1D10` は10のままです。サイゼリヤのメニューの照合・取得・注文はせず、番号を抽選する遊びです。チップは使いません。

### `!` を前置きしたときだけ料理名を表示

| 投稿 | 返信 |
|---|---|
| `サイゼロール` / `サイゼロールして` | 番号と出目のみ |
| `サイゼロール!` | 番号と出目のみ（末尾の!は指定になりません） |
| `!サイゼロール` / `!サイゼロールして` | 番号・出目に、参照表の料理名を追加 |
| `@Bot !サイゼロール` | メンションが必要な場合の料理名付き依頼 |

`!` は「サイゼロール」の直前に空白を挟まず付けます。全角の `！サイゼロール` も正規化して受け付けます。`!!サイゼロール` や `! サイゼロール` は受け付けません。引用・コード・説明・否定は引き続き対象外です。

例えば `!サイゼロール` で2407が出た場合は「ディアボラ風ハンバーグ」と参照元を追加します。参照表にない番号（例：3400）は「参照表にこの番号のメニューはありません」と表示し、勝手に振り直しません。**!なしでは料理名も参照表の照合結果も表示しません。**

参照元：[くろログ「サイゼリヤのメニュー番号対照表【2024年6月改定版】」](https://kurobo0408.hatenablog.com/entry/2024/09/22/205739)（2024-09-22公開、2026-10-25確認）。現在の販売内容・価格・店舗の提供を保証するものではなく、その旨と表の版を料理名付き返信に表示します。カードでは料理名を番号の下へ、版・注意をフッターへまとめ、見出しのリンクから参照表を開けます。文字返信の場合は参照リンクを本文に添えます。価格・画像・本文は転載せず、固定の式で出る120番号のうち表にある60件の番号・料理名を `src/saize-menu.js` に保持します。依頼のたびの外部通信・自動更新はありません。

保守時は指定記事の表と番号・名前を照合し、同じ番号の重複があれば一致を確認してから更新します。参照元URL・表の版・確認日と、対応件数のテストも更新してください。新しい表への差替えはコード更新として管理者が手動適用します。

既存のダイス返信とON/OFF・権限確認・重複防止・連投制限を共用します。通常投稿が読めない場合は `@Bot サイゼロール` と投稿してください。新しいコマンド・ボタン・設定・依存・保存データは追加しません。

## 通常の投稿で反応させる

Discord Developer Portal → Bot → Privileged Gateway Intents → **Message Content Intent** を有効にし、Botを再起動してください。起動時にDiscordのアプリ情報から有効化を確認します。既存のバックアップ読み上げで有効になっている場合は、その設定を使います。

未有効・確認できない場合でも、Botをメンションした `@Bot 1D100` のような投稿では利用できます。特権Intentを無条件に追加してBot全体のログインを失敗させることは避けます。Portal側の変更は再起動後に反映されます。

Botには対象チャンネルの閲覧・メッセージ履歴・送信、スレッドならスレッド送信権限が必要です。カード表示には「埋め込みリンク」権限を使います。権限がなければ文字で全内訳を返します。送信に失敗してから形式を変えて再送することはしません。アーカイブ・ロック済みのスレッドには返信しません。

## ON/OFF

既定はONです。管理者が `/admin → 運用・管理 → 設定を確認 → ダイス返信をOFF/ON` から変更できます。保存後に反映し、この切り替え自体に再起動は不要です。待機中のVC入室予約がある場合は既存の確認画面が表示されます。

## 制限とプライバシー

1投稿最大5式、各式1〜100個・面数2〜100万、合計200個、補正±100万までです。内訳は省略せず、受け付けた最大200個の出目をすべて表示します。10個ごとの改行と区切りで並べ、順序を維持します。短い連続操作は1ユーザー3件まで受け付け、その後は2秒ごとに1件分を回復します。全体にも頻度制限を設け、同時4返信までです。混雑時は反応を見送ります。

投稿本文を保存・ログ出力しません。30文字未満の関連する曖昧な候補だけ、設定済みの場合にBeatAPI経由のJevへ本文を送ります。投稿者・サーバー・チャンネルの情報や会話履歴は追加しません。抽選には暗号学的乱数を使いますが、第三者が検証できる抽選証明ではありません。個人情報やメンションは結果に引用せず、通知メンションも付けません。返信の結果が確認できない場合の自動再送は行いません。

更新は `/admin → バージョン管理` から通常どおり手動で行います。新しい実行依存はありません。Jevには起動環境の `BEATAPI_API_KEY` と、任意の `BEATAPI_JEV_MODEL` を使います。

## v5.3 操作の改善

「目星1D100」「聞き耳 1d100」「じゃあ目星で1D100振って」など、よく使う技能名と短い依頼も受け付けます。意味を尋ねる質問・説明・否定を見送る方針は維持します。使い方は `/menu → 使い方 → チャットダイス`、読取範囲とON/OFFは管理者の動作診断から確認できます。表示はBotのIntent設定に基づき、実際の投稿試験を行うものではありません。

## 文字数と長い式（v6.6）

通常の文章は**30文字未満**が対象です。30文字以上なら、返信・文字数エラー・AI送信のいずれも行いません。前後の空白とDiscordのメンション記法を除いて、絵文字もUnicodeコードポイント1個を1文字として数えます。メンション付き投稿も、Botの内部IDの桁数で不利にならないようにしています。

**式だけの投稿**は長さの例外です。`100000000d100000000000000000` や、さらに長い数字の式も黙って無視せず、個数・面数が上限を超える場合は既存の上限案内を返信します。巨大な値をそのまま抽選したり、Jevへ送ったりはしません。数字を小さな整数へ安全に変換できるかを先に確認します。サイゼの!条件と10→0、全内訳カードは維持します。

[BeatAPI・Jevの設定、無料版の制限と検証範囲](DICE_JEV.md)を参照してください。


## 使い方を分けて読む（v6.15）

`/menu → 使い方 → チャットダイス` は、基本の手順、高度なダイス、サイゼロール、準備・反映・終了、困ったときの案内を切り替えられます。30文字未満/純粋式の例外、文脈判断、全内訳、サイゼだけの10→0と!限定の料理名を維持し、案内を読んだだけでは抽選やAI照会をしません。[案内と比較](GUIDED_RECOVERY.md)。
