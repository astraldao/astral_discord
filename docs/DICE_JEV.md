# BeatAPI経由のJev 1.14・Noul（v6.6）

通常のダイス返信へ、曖昧な短文だけの補助判定を追加しています。Jevは生成AIへ文章の返答を書かせる方式ではなく、定義した質問へ型付きの判断値を返すモデルです。

## 判定の順序

1. Bot・Webhook・別サーバー・不完全な投稿は対象外。
2. 式だけの投稿は文字数の例外として、ローカルで構文と既存の個数・面数上限を確認。巨大な式も上限案内へ進め、AIへ送りません。
3. 通常の文章が30文字以上なら、返信せずAIにも送りません。前後の空白とDiscordメンション記法を除き、Unicodeコードポイントで数えます。
4. 式やダイス関連の語がなければ、AIへ送りません。`おはよう`・`手を振って`・`ロールケーキ食べたい` などは対象外。
5. `いけ！1d100`・`せーの1d20`・`そりゃ！3d6` など掛け声と式だけの投稿（v6.8）や、`1d10ふって`・`お風呂の温度は1D100度！！`・`!サイゼロール` など、明確な依頼や宣言はローカルで返信。式がない明確な「ダイス振って」には、式の入力案内を返します。
6. 説明・引用・コード・ネタバレ・否定・明確な過去の話などは見送ります。
7. 残った関連する曖昧な短文だけJevへ。`noul >= 0.8` の場合にローカルで抽選・返信します。式がなければ入力案内を返します。Jevへ式や結果を生成させることはありません。

`0.8` は判断閾値で（v6.8で0.9から変更）、日本語実データで較正済みの精度保証値ではありません。自由な文章の意味理解や、すべての曖昧な投稿への返信を保証するものではありません。通常の利用者別/全体の連投制限は、ローカル返信とAI候補で共用します。

## 接続先とモデル

- エンドポイント：`POST https://api.beatapi.io/v1/systemone`。
- 既定モデル：`jev-1.14-free`。BeatAPIでのJev 1.14の無料モデル名です。
- 質問：`questions.should_roll` の `type: "noul"`。
- 応答：`answers.should_roll.type === "noul"` と、数値型で0〜1の `noul`、要求したモデル名を確認します。
- `/v1/chat/completions` は使いません。`/v1/decisions` は公式の別名ですが、この実装は `/v1/systemone` に固定しています。

サンプリング・ストリーミング・画像・ツール呼び出しは使いません。Jevが判断できるのは返信可否のみです。個数・面数・補正の解析、暗号学的乱数、サイゼの料理名の公開条件はBot内で管理します。

## 設定

`.env.example` の項目を参照し、ホスティング側の秘密情報または非公開の `.env` に設定します。

| 起動環境の項目 | 意味 |
|---|---|
| `BEATAPI_API_KEY` | BeatAPIのサーバー用APIキー。未設定なら明確な依頼だけを処理し、曖昧な候補は見送る |
| `BEATAPI_JEV_MODEL` | `jev-1.14-free`（既定）または `jev-1.14`（常に有料）のみ |
| `BEATAPI_JEV_PAID_FALLBACK` | 無料版を使い切ったときに有料版 `jev-1.14` を使うか。未設定・`1` で使う（v6.7既定）、`0` で無料版だけ |

キーは[BeatAPIのAPI Keys](https://beatapi.io/dashboard/apikeys)で作成します。無料モデルには公式資料のdefault **auto group**が必要です。キーの値はDiscordやGitへ貼らず、管理コマンドのENV編集・診断・ログにも出しません。既存の管理者ENV編集は従来の許可項目のままで、APIキーを編集する入口は追加していません。

キー・モデルを変更した場合は、非公開 `.env` の変更でもホスティング側の起動環境の変更でも、**ホスティングパネルからプロセス全体を再起動**してください。親プロセスから継承された既存の環境変数が `.env` より優先されるため、Botのワーカー再起動だけでは古い値が残ることがあります。起動環境とファイルの両方に同じキーを置かず、運用する設定元を揃えてください。コードの更新は引き続き `/admin → バージョン管理` から手動で適用します。

## 料金と回数

2026-10-25に確認した[BeatAPI公式Decisions資料](https://docs.beatapi.io/decisions)では、`jev-1.14-free` は初回入金前に1成功呼び出し/分、入金後に最大10成功呼び出し/分です。アカウント単位の制限であり、Bot専用の枠ではありません。現在の料金・適用条件は公式資料を確認してください。

### 無料版を使い切ったら有料版（v6.7）

オーナーの指定により、無料版の回数を使い切った場合は有料版 `jev-1.14` で判定を続けます。

- 切り替えるのは、無料版がHTTP 429（`rate_limit_exceeded`、無料版の回数上限を含む）を返したときだけです。同じ投稿をその場で1回だけ有料版へ送ります。
- 無料版の `Retry-After` が過ぎるまでの新しい投稿は有料版へ送り、過ぎたら無料版へ戻ります。公式資料では無料版の回数はアカウントの通常の回数制限と別に数えられます。
- タイムアウト・認証エラー・500系・不正な応答では有料版へ送りません（料金がかかる再送をしない）。
- 有料版がHTTP 402（`insufficient_credits`、残高不足）なら10分、429なら `Retry-After` の間は有料版を使いません。無料版の待ち時間が過ぎれば無料版で再開します。
- 有料版の利用には残高が必要です。料金は[BeatAPIのダッシュボード](https://beatapi.io/dashboard/apikeys)と公式資料で確認してください。上限を決めたい場合はBeatAPI側の残高で管理するか、`BEATAPI_JEV_PAID_FALLBACK=0` にしてください。
- `BEATAPI_JEV_MODEL=jev-1.14` にすると最初から有料版だけを使います。

## 失敗・公開範囲

- API待ちは最大3秒、同時判定は最大2件、応答は8KiBまで。混雑分や失敗分は自動で並べ直したり再送したりしません。
- HTTP 429では `Retry-After`（最大5分）を尊重し、新しい投稿の受付まで待機します。古い投稿を時間後に再送しません。
- タイムアウト、HTTPエラー、不正な型・JSON・モデル名、閾値未満なら返信を見送ります。APIのエラー本文や生成物はDiscordへ出しません。
- 送るのは保護領域とメンション記法を除いた候補本文だけ。投稿者/サーバー/チャンネル情報・履歴・設定・読み上げ内容を付け足しません。Bot内では候補本文・判断値を永続保存しません。外部サービス側の取り扱いはBeatAPIとTypeSafeの規約・ポリシーに従います。
- **外部送信の直前**に元投稿・現在の権限・ON/OFFを確認。判定後も本文・権限を再取得し、編集・削除・権限喪失・OFFになっていれば抽選も返信もしません。
- サイゼの料理名はローカルで確認した直前の!がある場合だけ。Jevはこの公開条件を変更できません。

## 動作診断

`/admin → 運用・管理 → 動作診断` で、Jevの設定済みフラグ、許可されたモデル名、有料版への切り替えの有無、直前に使ったモデル、直前の有限な状態（待機・判定・回数制限・残高不足・タイムアウト等）を表示します。キーや元の文章は表示せず、診断を開くだけでJevを呼ぶこともありません。「設定済み」はキーがあるという意味で、認証・接続の成功を保証しません。

## v6.8 の調整

「いけ！1d100」に反応しないという報告を受けて調整しました。

- **掛け声はJevへ送らずローカルで返信**：いけ・行け・いっけー・せーの・えいっ・そりゃ・おりゃ・くらえ・ほい・どうだ・よし・いざ など、掛け声と式だけの短文は明確な依頼として扱います。API代・待ち時間・回数制限の影響を受けません。「行けない」などの否定、「って何」などの質問、引用は従来どおり見送ります。「それ1d100」「それは1d100」は説明の可能性があるためJevへ送ります。
- **質問文の調整**：Discordのダイスbotという前提と、短い投稿は依頼であることが多いことを明記し、返信する例（いけ！1d100・せーの1d20・運試し1d100・この1d10どうしよう）と返信しない例（1d100って何・期待値・さっき出た結果の報告）を追加しました。投稿本文は従来どおりデータとして扱い、中の指示には従いません。
- **閾値を0.9→0.8**：短い掛け声が0.9に届かず見送られる例があったためです。実データで較正した値ではありません。
- **動作診断に直前の判定値**：`判定値0.73（0.80以上で返信）` のように表示します。本文は表示しません。見送りが多いときは、この値を見て閾値をさらに調整できます。
