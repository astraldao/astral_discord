# メイン・サブサーバーの連携

同じBotを2つのDiscordサーバーで使えます。入口は `/admin → 運用・管理 → サーバー連携` です。追加のスラッシュコマンド、トークン入力、新しいENVはありません。サブへBotを招待する操作は管理者が行います。

## サブで同じ機能を使う

1. メインで「サーバー連携」を開き、招待リンクから同じBotをサブへ追加します。
2. 両サーバーで、実行者とBotに管理者権限を用意してください。サブではBot専用ロールに付与し、@everyoneだけに依存しないようにします。
3. 「サブサーバーを登録」でサブのIDを入力し、確認画面から有効にします。
4. サブでも `/menu` と `/admin` を使えます。VCのロビー・行き先などはサブ側で設定してください。

メインの既存 `data/*.json` は移動しません。サブの設定・読み方・予定・TRPG・チップは `data/guilds/<サブID>/*.json` に分離します。メインの残高や予定がサブへ勝手に渡ることはありません。連携情報は `data/server-network.json` に保存します。データ領域全体が従来の手動更新バックアップの対象です。

Botのバナー・更新・再起動・ENV・音声モデル・Jev接続は1プロセスで共通です。画像変換・バナー変更の排他/間隔と、音声入室のキューも共用し、読み上げはBot全体で同時1組です。共通設定の操作/測定には、操作先に加えメイン側の管理者権限も必要です。音声・測定・進行中ゲームは両サーバーを確認してから更新します。サブ初期化だけの失敗はメインを停止させません。

## 構成コピー

v7.1から、**サブの既存構成を削除してメインの構成で作り直します。** 既存AutoModや通常ロールがあっても、コピー対象として削除します。**チャンネル削除では投稿・添付・スレッド・チャンネルのWebhookなども失われ、復元できません。** コピー先のサーバー名・基本設定・@everyone権限も変更します。

削除するのは、サブの既存チャンネル/カテゴリ、通常ロール、AutoMod、手動の絵文字、スタンプ、サウンド、サーバー画像です。@everyoneは削除せず権限を上書きし、Bot/外部連携の管理ロール・管理絵文字はDiscordの仕様上保持します。メンバーを追放したり、Bot内の予定・TRPG・チップ・設定JSON、BAN、外部連携やコピー対象外のサーバー項目を消去したりする機能ではありません。通常ロールの削除では、メンバーの既存ロール割当も失われます。

実行手順：

1. **サブの所有者**が、メイン側の管理者として「構成をコピー」を開きます。サブ側からは実行できません。
2. Botの管理ロールに管理者権限を付与し、削除するすべての通常ロールより上に置いてください。サブのコミュニティ設定はメインと同じ状態にします。
3. コピー件数・削除件数・対象外の項目を確認します。この段階は読み取りだけです。
4. 「削除内容を確認…」から、削除対象の**サブサーバーID**を入力して実行します。メインのIDや誤ったIDでは実行しません。

ロール削除後も管理権限を維持できるよう、所有者とBot管理ロールを実行条件にしています。スレッド同期設定がある場合は、同期先の消失を防ぐため開始しません。以前のコピー記録があるサブへの再実行も、自動で記録を破棄して続行しません。

| 対象 | 内容 |
| --- | --- |
| ロール | 名前・権限・色・別表示・メンション可否・順序。メンバーへの割当は移植しません |
| チャンネル | カテゴリ・テキスト・アナウンス・VC・ステージ・フォーラム・メディア、親子関係・順序・話題・NSFW・低速モード・VC設定 |
| 上書き権限 | ロールID/@everyoneをコピー先のIDへ置換。個別メンバー権限は対象者がサブにも必要です |
| フォーラム | タグ名・要承認設定・対応可能な絵文字・既定の反応・並び/表示設定 |
| コミュニティ | オンボーディングの質問・選択肢・ロール/チャンネル参照、既定チャンネル・ウェルカム画面。先にサブのコミュニティを有効にしてください |
| 素材 | 絵文字と利用ロール、スタンプ、サウンドボード、アイコン、条件を満たすバナー/招待背景/発見ページ画像 |
| AutoMod | サブの既存ルールを削除し、メインのトリガー・動作・除外ロール/チャンネルを対応表で置換 |
| サーバー設定 | 名前・認証レベル・通知・不適切コンテンツ設定・AFK・システム/ルール/更新用チャンネル・ロケール |

アナウンス/ステージ/フォーラム/メディアを含む場合、先にサブのコミュニティを有効にしてください。Discordの機能枠・ブースト枠・素材の容量上限は引き継げません。VCのビットレートはコピー先の音質上限に合わせ、プレビューで案内します。Bot/連携管理ロールは作成できません。同じBotの管理ロールが両側にある場合だけ対応付けます。解決できないロール参照や個別権限があれば、権限を省略して作成せず停止します。カスタム絵文字が移植できない場合、元IDを誤用しません。

**メンバーの強制移動、参加済みロール割当、過去メッセージ・スレッド全履歴、招待、Webhook、外部連携、ブースト、独自URL、サーバーガイド、規約本文、ロールアイコンは完全移植しません。** Discordの設定・契約・本人操作に依存するため「何もかも完全に同一」にはできません。Bot内の予定・TRPG・チップ・読み方も、この構成コピーには含みません。

コピー中は件数と停止ボタンを表示します。停止は進行中の1件が終わり次第反映し、作成済みを残します。削除した構成・投稿は戻せません。実行直前に構成の変更を検知したら、プレビューを作り直します。削除を含む各API操作前に実行記録を保存し、作成結果のIDを保存します。途中失敗や切断時は作成済みを残します。結果不明の削除・作成は再送しません。同じサブへの構成コピーは未解決の記録があれば開始しません。最初の準備だけを確認済みにできた場合の例外は、下の停止時の手順を参照してください。実行記録がある状態でやり直したい場合は、自動削除せず管理者が構成を確認してください。

## 指定チャンネルのスレッド同期

1. 両側に同種のチャンネルを用意します。構成コピーで作ったチャンネルも使えます。
2. フォーラムでは、同名・同じ要承認設定のタグを揃えます。
3. メイン側の元チャンネルIDと、サブ側の先チャンネルIDを入力します。
4. **両側の閲覧権限と公開範囲**を確認し、同期を開始します。内容はサブの閲覧者にも公開されます。

通常投稿の本文を読むにはDeveloper PortalのMessage Content IntentとBotの再起動が必要です。有効でない場合は開始できません。

メイン→サブの片方向で、公開スレッドの新規投稿・編集・削除、タイトル・タグ・低速モード・アーカイブ/ロックを反映します。元投稿の本文はBot名で投稿し、投稿者名と元リンクを添えます。@everyone/ユーザー/ロールへ通知しません。投稿者をWebhookで偽装しません。サブの返信はメインへ送らず、無関係なスレッド/投稿を変更しません。

添付は期限付きリンクの案内です。実ファイルの再保存や再添付ではありません。非公開スレッド、リアクション、投票、スタンプなどは再現しません。元の投稿に戻って確認できます。通信・レート制限により遅延するため、厳密な同時更新は保証できません。

開始/再開/差分確認は最近20スレッド×各50投稿までです。過去全履歴の移行や停止中のすべての変更の再現ではありません。選ばれた最近のスレッドでは、記録済みの投稿について停止中の編集と削除も照合します。通常テキストの元投稿から作ったスレッドは、親チャンネルの先頭投稿とその編集/削除も反映します。最大8チャンネル組、各200スレッド/2000投稿、待機100イベント。上限時は停止し、記録を勝手に捨てて再投稿しません。

各連携を作成した人の両サーバーの管理権限とBot権限を、送信・編集・削除前に再確認します。権限失効・参照先の不一致・結果不明時は停止します。通常の再起動後は権限と最近の差分を再確認して続行します。結果不明の操作と管理者が手動停止した連携は停止を保持します。状態には実行段階・対応ID・件数を表示します。「送信結果を探す」は既存のBot投稿/スレッドを読み取る復旧で、新規投稿はしません。一意に確認できない場合は停止したままにします。

## 検証範囲

自動テストと実際のDiscord SDKのデータ形式/送信形式を検証します。Discordの実サーバー、コミュニティ要件、ブースト枠、実際のレート制限下でのコピー/同期は別途確認が必要です。まず新しいサブとテスト用チャンネルで確認してください。

## 更新・ロールバック

Bot全体の更新は従来どおり `/admin → バージョン管理` から手動です。サブ導入のためのENV編集や追加トークンはありません。v6系へ戻すとサブ機能は動作しませんが、メインの既存JSONを維持し、サブのファイルも自動削除しません。

[架空データの6画面見本](previews/server-network-v7.html) は `node scripts/preview-server-network.js > docs/previews/server-network-v7.html` で再生成できます。画面/PC幅/390px幅を切り替えられますが、カード内の操作は実行しません。生成デザイン用12ui CLIの認証確認はサインインサービスへの接続失敗で利用できず、既存のDiscord標準カード規則で作成しています。画像生成に成功したという記録ではありません。

## 構成の確認で失敗した場合

v7.0.1から、確認用の読み取り中に止まった場合は「コピーは開始していません」と表示します。「確認をやり直す」はプレビューを再取得するだけで、ロール/チャンネルの作成はしません。修正後のプレビューを確認し、実行ボタンを押して初めてコピーします。

エラーには「サブのスタンプ」などの取得項目と、`sub-stickers / DISCORD_50013` のような診断コードを表示します。Botの参加・管理権限や対象設定を確認してください。通信障害やDiscordの制限時は、少し待ってから確認し直します。コンソールにも同じ段階/コードを記録しますが、内部エラー本文・リクエストURL・トークンは表示しません。

ウェルカム画面が未設定のときにDiscordが返す10069だけは、取得失敗ではなく「未設定」として扱います。v7.1の削除コピーでは、メインが未設定ならサブの既存ウェルカム画面を空にします。v7.0系の追加コピーでは未設定項目を変更しませんでした。権限不足・一般的な404・他の項目のエラーを空の設定として無視することはありません。

コピー実行後の「結果不明」は別の状態です。未開始用の確認ボタンで再コピーせず、作成済みの構成と処理記録を確認してください。

AutoModの作成前チェックは[Discord公式の種別別上限](https://docs.discord.com/developers/resources/auto-moderation#trigger-types)に従います。既存ルールは削除するため、サブ側の既存件数を追加先の枠として二重に数えません。

## コピー実行中に停止した場合

v7.1.1から、「サブの既存オンボーディングを空にする」などの停止箇所と、`sub-reset-onboarding / DISCORD_350001` のような診断コードを表示・記録します。画面を更新する段階の失敗は `interaction-response` と分けます。SDK内部の本文・URL・リクエスト・トークンは表示しません。

「処理記録を確認」は状態の表示だけです。完了を確認した操作件数、結果確認待ちの処理、直近の診断コード、一時退避チャンネルの記録を確認できます。旧版の記録に完了件数/コードがなければ、後から推測せず不明と表示します。削除や作成の結果不明を自動で再実行しません。

メイン側の操作欄に「準備の状態を確認」がある場合は、最初の `reset-onboarding` だけで止まった記録を検査できます。実行者が元の操作本人かつ現在のサブ所有者で、サーバー/権限/記録が一致し、メインとサブ両方のオンボーディングが実際に無効・モード0・質問0・既定チャンネル0であること、作成済みや退避先の記録がないことを読み取りで検証します。ロール対応も@everyoneか対応済みのBot管理ロールだけと確認します。

コピー元も空であることを条件にするのは、古い空化要求が遅れて到着しても、新しい非空の設定を消さないためです。条件を満たせば、旧記録は削除せず「準備確認済み」の履歴として残します。その後、管理者が「構成をコピー」から新しい削除対象を確認し、サブIDを再入力して初めて新しいコピーを実行します。準備の確認自体はDiscordへ変更を送りません。履歴は上限10件です。空状態を確認できない場合や、削除・作成・退避が進んだ記録は保持したまま停止します。

既に空のオンボーディング/ウェルカム画面への空化や、コピー元の空設定を再度適用する不要なPATCHは省略します。未設定・空である証拠がない設定を飛ばしてコピーすることはありません。Discordの仕様は[オンボーディング](https://docs.discord.com/developers/resources/guild#modify-guild-onboarding)と[エラーコード](https://docs.discord.com/developers/topics/opcodes-and-status-codes#json)を参照してください。表示されたコードなしで403の原因を権限不足やBot制限と断定しません。
